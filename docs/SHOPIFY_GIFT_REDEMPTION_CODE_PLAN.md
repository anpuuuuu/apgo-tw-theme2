# Shopify 指定贈品兌換碼方案

> 建立日期：2026-08-24  
> 目前狀態：方案已記錄，尚未實作  
> 原則：使用 Shopify 原生折扣與 APGO 現有折扣碼輸入框；不使用 AIOD 的另一個輸入 Widget，不建立自製 App。

---

## 1. 需求

顧客完成指定的回饋活動並經小編審核後，取得一組代碼；下次在 APGO 官網購物時輸入代碼，兌換指定贈品。

此需求不能用 Gift Card 處理，因為 Gift Card 是金額，不能可靠限制成某一件贈品。

---

## 2. 推薦方案

使用以下三個 Shopify／主題能力：

1. Shopify 原生商品折扣或 Buy X Get Y 折扣。
2. Shopify 的指定顧客群組資格與每位顧客一次限制。
3. APGO 現有購物車折扣碼輸入框與自動加入贈品邏輯。

AIOD 可以繼續處理其他促銷，但不管理本活動贈品碼，也不顯示第二個代碼輸入框。

---

## 3. 顧客流程

```text
顧客完成符合規定的回饋活動
        ↓
私訊小編並提供可辨識的會員資料
        ↓
小編審核並把顧客加入本期活動名單
        ↓
小編私訊贈品碼
        ↓
顧客在 APGO 購物車現有折扣碼欄位輸入
        ↓
主題自動加入指定贈品
        ↓
Shopify 驗證顧客資格、商品、效期與使用次數
        ↓
符合資格時贈品折抵為 NT$0
```

若顧客尚未被 Shopify 辨識，可能要登入會員，或在 Checkout 填入與 Customer 資料一致的 Email／電話後，才能完成資格驗證。

---

## 4. 防止代碼外流

### 推薦：共用活動碼＋限定顧客群組

不要只靠隨機碼。正確防護方式是限制誰有資格使用：

1. 每一期建立獨立 Customer tag，例如 `gift-2026-09-eligible`。
2. 建立條件為該 tag 的 Shopify Customer segment。
3. 折扣 Eligibility 設為此 segment，不設為 All customers。
4. 限制每位顧客一次、每張訂單一件贈品。
5. 視活動設定最低消費、折扣組合規則與截止日期。

即使共用碼被公開，不在本期活動名單中的顧客仍不能使用。Shopify 原生折扣支援 Specific customers、Customer segments、總使用次數與每位顧客一次限制。[Shopify 折扣資格設定](https://help.shopify.com/en/manual/discounts/managing-discounts)

### 低量活動：每人獨立隨機碼

若每期只有少量顧客，可以替每位顧客建立一組不同的隨機碼，並設定：

- 只限該名 Specific customer。
- 總使用次數一次。
- 每位顧客一次。
- 只適用指定贈品。
- 指定有效期限。

這種方式更容易追溯是哪一位顧客的代碼外流，但每位顧客都要建立一筆折扣，人工維護量較大。

### 不足以防外流的設定

- 只有隨機碼：被截圖或轉傳後仍可被別人搶先使用。
- 只有「每位顧客一次」：知道代碼的每位顧客仍可能各使用一次。
- 只有「總使用一次」：可能被非原本領取者搶先兌換。

---

## 5. Shopify 折扣設定

預計設定如下，實際值等活動拍板後填入：

| 設定 | 建議值 |
|---|---|
| Code | 每期一組，例如 `FEEDBACK-GIFT-2026-09` |
| Discount type | 商品 100% off 或 Buy X Get Y |
| Applies to | 指定贈品 variant |
| Eligibility | 本期 Customer segment |
| Maximum uses | 每位顧客一次 |
| Quantity | 每張訂單只折一件 |
| Minimum purchase | 依活動規則決定 |
| Combinations | 原則上不與其他商品折扣併用 |
| End date | 設定活動截止時間 |

## 6. APGO 主題需求

現有折扣碼欄位可以繼續使用，但主題必須知道活動碼對應哪個贈品，才能自動加入正確 variant。

目前程式使用寫死的「完整代碼 → 贈品 variant」對照方式。實作時應改成可維護的活動設定，例如：

- 共用活動碼時：每期增加一筆活動設定。
- 多組獨立碼時：使用安全的活動前綴辨識同一贈品，Shopify 仍負責最終代碼與顧客資格驗證。
- 長期方案：使用 Shopify Metaobject 管理活動碼／前綴、贈品 variant、效期與啟用狀態。

目標是以後新增活動只改 Shopify 後台設定，不重寫整套購物車程式。

### 前端失敗處理

```text
輸入代碼
  ↓
暫時加入贈品
  ↓
Shopify 驗證折扣
  ├─ 有效：保留贈品並顯示成功
  └─ 無效／無資格：移除贈品並顯示原因
```

若顧客要到 Checkout 輸入 Email 才能被辨識，購物車階段可能只能做初步驗證；Shopify Checkout 的結果才是最終判定。實作與測試必須涵蓋登入、未登入、LINE／HIKO 登入與 Email 不一致等情況。

---

## 7. 後台維護與查錯

### 每期活動建立

1. 建立活動 Customer tag 與 segment。
2. 建立 Shopify 原生折扣。
3. 設定贈品 variant、每人一次、組合規則與截止日。
4. 在主題活動設定中加入代碼／前綴與贈品對應。
5. 使用合格與不合格測試帳號各測一次。

### 小編日常操作

1. 審核顧客提供的活動資料。
2. 在 Shopify Customer 加上本期 eligible tag。
3. 私訊活動代碼。
4. 若有爭議，查顧客 tag、折扣使用次數、訂單折扣明細與活動期限。

### 問題排查順序

1. 顧客輸入的 code 是否完全正確。
2. Customer 是否有本期 eligible tag。
3. Checkout Email／電話是否對應到同一個 Shopify Customer。
4. 贈品 variant 是否存在、上架且可加入購物車。
5. 折扣是否啟用、過期、達使用上限或被組合規則擋住。
6. 主題的 code／prefix 是否指向正確 variant。
7. AIOD 或其他折扣 App 是否同時修改該商品或購物車。

---

## 8. 政策風險

不可將贈品條件限定為「Google 五星好評」。以贈品、購物金或折扣換取指定正面公開評價存在平台政策風險。活動文案與審核條件應改為私人問卷、購買體驗回饋，或由負責同事確認符合平台規則的其他形式。

技術上的兌換碼方案可以完成「審核後送贈品」，但不能消除原活動文案本身的政策風險。

---

## 9. 實作前待決定

1. 採用「共用碼＋活動名單」還是「每人獨立碼」。目前推薦前者。
2. 活動的合規名稱與審核條件。
3. 贈品 product／variant。
4. 是否要求下次購物達最低金額。
5. 是否允許與其他商品或訂單折扣併用。
6. 活動開始日、截止日與每位顧客的兌換次數。
